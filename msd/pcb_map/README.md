# Whisker PCB header map

`make_map.py` builds a standalone HTML page that maps the MSD P25937 whisker PCB (rev 2): which header pins each strain gauge plugs into (J2–J5), the ESP32 control headers P1 (ADC SPI) and P2 (mux selects) with the ESP32 GPIO and DevKit V1 board pin for each, the pinout of both CD4097B muxes (what each pin carries, with suspect channels marked), and how to route the ESP32 ground wire. The published copy is `/shared/rc/whiskers/MSD_P25937/whisker_header_map.html`, and a copy is kept at [`../docs/whisker_header_map.html`](../docs/whisker_header_map.html).

```bash
pip install olefile
python msd/pcb_map/make_map.py whisker_header_map.html
```

Inputs, all read directly (no unzipping):

- `--altium-zip` (default `/shared/rc/whiskers/MSD_P25937/P25937_Whisker_Final.zip`): `PCB0603.PcbDoc` gives component positions, pad positions and pad nets.
- `--gerber-zip` (default `/shared/rc/whiskers/MSD_P25937/REV2_GERBER.zip`): `PCB0603_Legend_Top.gbr` gives the silkscreen drawn under the board view.
- `--firmware` (default `msd/esp32/whisker_daq/whisker_daq.ino`): the `PIN_*` defines give the ESP32 GPIO for each P1/P2 signal, so the page follows the firmware.

`make_signal_chain.py` writes the companion page `whisker_signal_chain.html`: a schematic of one whisker (W1, gauges A and B) from the gauges through the quarter bridges, INA351s, RC filters, mux and ADC to the ESP32 and host, plus the shared REF divider and power. It is hand-drawn from the traced nets and has no inputs: `python msd/pcb_map/make_signal_chain.py whisker_signal_chain.html`.

`signal_chain_anim.html` is a hand-written, self-contained animated page (no generator, no build step; open it in a browser) that simulates one reading end to end: gauges with noise, the 845 Hz ripple and the 62.5 Hz comb, the mux switch disturbance (bench settle model: ~0.0136 × step, τ ~80 µs, +25 µs for a railed source), a 1st/2nd-order delta-sigma modulator bit by bit, the sinc3 filter and 24-bit codes, DRDY/SPI, the legacy (settle, discard N, keep 1) and locked (N conversions per scan, average those whose window starts ≥ settle) firmware policies, and the frame with its error vs the true input. Mux positions and ADC channels are parameters: the default is a 4×2 mux and 2 ADC channels, and the "real board 8×4" preset has all 32 gauges. Presets cover the legacy 76 Hz scan, quiet 62.5 Hz (OSR 256), wide 250 Hz (OSR 128) and a teaching setting (OSR 16). URL hash options set the state, e.g. `#preset=teach&pause&slot=1,1,150&theme=dark` (`goto=s4` scrolls to a section). Layout and speed: every canvas has a fixed height (set from the topology only) and changing text sits in fixed single-line rows, so the page never changes height while it plays; lanes off screen are not drawn, static layers are cached, and text updates run at ~10 Hz. `#perf` runs 300 frames and reports frame times, the page height and the scroll position as JSON. A copy sits beside the signal chain page in `../docs/`, which links to it. Test (needs Chromium; run on a compute node): `CHROMIUM=~/app/chromium pytest msd/pcb_map/test_signal_chain_anim.py`. It runs the page's `#selftest` and checks the modulator against the chain page's worked examples and accuracy table (functions taken from `make_signal_chain.py`), DC codes through the whole pipeline, the settle tail, the discard/keep rules, the scan rates, and (via `#perf`, every preset at 1400 and 900 px) that the page height and scroll position stay constant over 300 frames.

Files: `pcbdoc.py` is a minimal Altium PcbDoc reader (Components6, Nets6, Pads6, Board6 streams; binary pad layout as in KiCad's Altium importer). `gerber.py` is a minimal Gerber RS-274X reader (strokes, regions, flashes). `page.html` is the page template (styles and static text); `make_map.py` fills in the SVGs and tables.

Hand-entered facts, not read from the files: the gauge pin pairing (from the schematic MAIN sheet, checked by asserts against the PCB nets), the firmware/wavi_py whisker naming (W(n)_A = OUT(2n−1)), the ADS131M04 and CD4097B pin functions (the mux pin → OUT assignment is checked by asserts against the firmware's `OUT_OF` table), the bench state (which REF divider copy is fitted, suspect mux channels), and the DevKit V1 30-pin header order (DOIT layout; check your board's labels). The whisker numbering was verified on the bench: J2 pins 1–4 show up as W1 in wavi_py.

Things the map found that are easy to get wrong: the silkscreen "MUX1"/"MUX2" labels are the opposite of the net names (mux 1 = SEL*_1 = OUT1–16 is the lower chip, printed "MUX2"); P1 and P2 have no GND pin (the through-hole GND points are MD1 pin 2, the middle lead of the 3.3 V buck module, and J1 pin 4); the P1 net names (PIN23, PIN21, …) are Raspberry Pi header positions from the original design. The INA351 REF divider (R7 3V3→REF, R8 REF→GND, C4) exists twice, because MAIN.SchDoc places the Amplifier_Reference sheet twice; both copies sit on the one AMP_REF_3V3 net, at the top and bottom board edges, and the schematic values (100 k/100 k, 1.65 V) would rail every channel.
